# 기술 아키텍처 백서: 엔터프라이즈 생성형 AI의 실체와 결정론적 시스템 설계

- **문서 버전:** v1.0
- **작성일:** 2026년 11월 18일
- **핵심 주제:** LLM, 에이전틱 AI, 온톨로지, 멀티모달의 시스템 공학적 해부 및 한계 정의

## 요약 (Executive Summary)

현재 산업계를 지배하는 생성형 AI(LLM, 에이전틱 AI, 온톨로지, 멀티모달)에 대한 서사는 과도한 의인화와 마케팅적 수사로 포장되어 있다. 그러나 시스템 공학 및 엔터프라이즈 데이터 아키텍처의 관점에서 그 껍질을 벗겨내면, 이 기술들의 본질은 지능의 창발이 아니다.

이는 "인간이 수작업으로 축적하고 구조화한 마스터 테이블(Master Table)과 원장 데이터를, GPU 병렬 연산이라는 물리적 속도를 동원해 확률적으로 초고속 매칭·조합해 주는 인터페이스 계층(Glue Layer)"에 불과하다. 본 백서는 4대 핵심 AI 패러다임의 실체를 엔터프라이즈 시스템 관점에서 냉정하게 해부하고, 실무 적용을 위한 현실적 아키텍처 기준을 제시한다.

## 1. LLM (대형 언어 모델): 거대한 확률적 전화 교환원

### 1.1 작동 본질

LLM은 개념을 이해하거나 진리를 추론하는 두뇌가 아니다. 인터넷상의 방대한 비정형 텍스트(논문, 일상 대화, 코드 등)를 학습하여, 특정 문맥(Input)이 주어졌을 때 다음에 이어질 토큰(단어 조각)의 통계적 확률을 계산하는 초거대 확률 분포 모델이다.

### 1.2 병렬 연산과 인터페이스의 역할

- **병렬 매칭(Transformer):** 순차적 사고가 아닌 어텐션(Attention) 메커니즘을 통해 문맥 내 모든 단어 간의 상관관계 가중치를 병렬로 한꺼번에 연산한다.
- **창구 직원(교환원) 아키텍처:** 수많은 화자의 데이터가 섞인 거대한 통계적 교집합에서 가장 그럴싸한 평균값을 뽑아 정돈된 텍스트로 출력한다.
- **UI 대체재로서의 목적:** 완벽한 마스터 테이블과 대시보드(UI)가 존재한다면 사용자가 직접 클릭하는 것이 100배 빠르고 정확하다. LLM은 "클릭할 줄 모르거나, 버튼(UI)을 만들어 두지 않은 비정형 영역"에서 사용자의 자연어 의도를 받아 백엔드 시스템의 정형화된 실행 트리거(SQL, API)로 변환해 주는 범용 텍스트 파서(Parser) 역할을 수행한다.

## 2. 에이전틱 AI (Agentic AI) & 하네스: 마스터 테이블 기반 VLOOKUP 실행기

### 2.1 결정론적 세계(SCM/ERP)와 확률 모델의 충돌

공급망 관리(SCM), 재무, 생산 관리 등 엔터프라이즈 핵심 영역은 1원, 1개 단위의 오차도 허용되지 않는 결정론적(Deterministic) 시스템이다. 확률적 추정치에 기반한 LLM이 직접 수량을 계산하거나 발주를 내리면 시스템은 즉각 붕괴한다.

### 2.2 하네스(Harness)의 실제 구동 원리

자율적으로 사고하고 행동하는 것처럼 포장된 에이전틱 AI와 프레임워크(하네스)의 내부는 다음과 같은 하드코딩된 상태 기계(State Machine)로 작동한다.

| 단계 | 처리 주체 | 실제 수행 작업 | 시스템적 본질 |
|---|---|---|---|
| 1. 의도 수신 | 사용자 | 비정형 자연어 텍스트 입력 | 비정형 쿼리 발생 |
| 2. 키값 추출 | LLM 파서 | 텍스트에서 Entity(일자, 부서, 품목코드) 추출 | 정형 파라미터 파싱 |
| 3. 스니펫 매칭 | 라우터/하네스 | 사전 정의된 API/함수 목록에서 적합한 툴 선택 | 조건문 분기 및 VLOOKUP |
| 4. 연산 실행 | 레거시 DB/코드 | SQL 쿼리 및 파이썬 스크립트 실행 | 결정론적 원장 조회 |
| 5. 결과 포장 | LLM 생성기 | 반환된 정형 데이터를 자연어 템플릿에 삽입 | 출력 포맷팅 |

### 2.3 구축의 현실: '마스터 테이블 노가다'

에이전틱 SI 프로젝트에서 LLM 프롬프트 엔지니어링이 차지하는 비중은 극히 미미하다. 전체 공수의 절대다수는 레거시 데이터를 정제하고, 기준 정보(Master Data)를 표준화하며, 예외 상황별 실행 스니펫을 수작업으로 매핑하는 데이터 엔지니어링 노가다에 투입된다.

## 3. 온톨로지 (Ontology): 원장 추적(Audit Trail)을 위한 관계형 스키마

### 3.1 엑셀 셀 참조 추적기의 확장

재무와 SCM에서 가장 중요한 것은 특정 수치가 도출된 근거를 역추적하는 원장 추적성(Traceability)이다. 엑셀에서 수식이 걸린 셀의 참조 관계를 화살표로 역추적하는 것과 마찬가지로, 온톨로지는 기업 내 개념, 자산, 데이터 간의 인과와 종속 관계(Relation)를 사전에 촘촘하게 엮어 놓은 거대한 관계형 그래프 명세서다.

### 3.2 온톨로지와 LLM의 결합 구조

- 온톨로지 자체가 지능을 가진 것이 아니라, 사람이 수작업으로 설계한 정밀한 관계형 마스터 테이블(Graph DB)이 뼈대를 이룬다.
- LLM은 사용자가 복잡한 그래프 쿼리(Cypher, SPARQL 등)를 직접 작성하지 않고도 자연어 질문을 던졌을 때, 온톨로지 그래프의 어떤 노드(Node)와 엣지(Edge)를 탐색해야 할지 경로를 지정해 주는 프론트엔드 리모컨으로 기능한다.

## 4. 멀티모달 (Multimodal): 통합 좌표 매핑 기반의 확률적 이어 붙이기

### 4.1 포맷만 바뀐 동일한 토큰 이어 붙이기

텍스트, 이미지, 오디오는 인간에게 다른 감각으로 다가오지만, AI 시스템 내부에서는 모두 동일한 숫자 배열(텐서)로 처리된다.

- **이미지/영상:** 노이즈 상태에서 텍스트 조건에 부합할 확률이 가장 높은 픽셀 배치를 역산하여 이어 붙인다.
- **음악/오디오:** 앞선 주파수(스펙트로그램)나 MIDI 시퀀스 뒤에 올 확률이 가장 높은 파형 조각을 이어 붙인다.

### 4.2 임베딩(Embedding) 마스터 공간의 한계

멀티모달 모델은 서로 다른 데이터 포맷을 고차원 벡터 공간이라는 하나의 공통 마스터 테이블에 강제로 매핑해 둔 구조다. 따라서 물리 법칙의 엄밀함(악기 운지, 화성학, 인체 해부학 등)을 논리적으로 이해하고 창작하는 것이 아니라, 과거 학습 데이터의 통계적 평균치를 조합해 '가장 그럴싸한 B급 모방 결과물'을 생성하는 데 그친다.

## 5. 종합 결론: 시스템 아키텍트를 위한 3대 원칙

생성형 AI 기술의 본질은 '과거 인간이 축적한 데이터의 양'과 'GPU 병렬 연산의 속도'라는 두 가지 물리적 변수에 종속되어 있다. 이 기술이 가진 '통계적 B급 평균치'라는 태생적 한계를 인정할 때 비로소 실무에서 작동하는 견고한 시스템을 설계할 수 있다.

- **연산과 판단의 분리:** 확률 모델(LLM)에게는 오직 '비정형 텍스트의 정형화(Parsing)'와 '결과 요약'만 맡긴다. 수치 계산, 재고 할당, 회계 처리는 반드시 검증된 마스터 테이블과 결정론적 코드(SQL/Python)가 수행해야 한다.
- **마스터 데이터 우선주의:** 화려한 에이전트 프레임워크를 도입하기 전에, 시스템의 기준이 되는 마스터 테이블과 온톨로지(원장 관계도)를 완벽하게 구축하는 것이 선행되어야 한다. 쓰레기 데이터 위에서는 초고속 병렬 연산도 쓰레기만 빠르게 찍어낼 뿐이다.
- **도구로서의 명확한 위치 지정:** AI는 인간을 대체하는 자율적 주체가 아니라, 복잡한 백엔드 시스템과 마스터 테이블을 자연어 한 줄로 제어하기 위해 얹어놓은 고성능 인터페이스 리모컨으로 정의하고 활용해야 한다.
